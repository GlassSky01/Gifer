# Gifer

把若干张图片做成一张带「扫描线擦除」过渡的 GIF。**纯静态、零依赖、零构建**，全部在浏览器本地完成，图片不会上传到任何地方。

## 用法

**双击 `index.html` 就能用** —— 不需要服务器、不需要安装任何东西、不需要联网。只保证 Chrome / Edge。

1. 点「添加」选图（也可以把图片拖到左侧列表，或直接 `Ctrl+V` 粘贴）
2. 拖拽缩略图调整顺序，悬停点 `×` 移除
3. 点「预览」看效果，点「保存」下载 GIF
4. 刷新即清空，不留任何数据

## 效果

从第一张到最后一张循环播放。每次切换时，从左侧出现一条竖直的扫描线，**匀速**向右前进，扫过的位置变成下一张图；扫到右边界后消失，接着停留一会儿再切下一张。

## 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| 过渡 | 700ms | 扫描线从左走到右的时长 |
| 停留 | 700ms | 每张图完全显示后的停顿 |
| 目标体积 | 1.0MB | 超过就自动降级重编；可设为「不限」 |
| 留边背景 | 纯白 | 图片比例不一致时的留边颜色，可选纯黑 / 首图主色 |

画布比例跟随第一张图，图片按 `contain` 缩放（不裁切）。

## 体积控制

GIF 只有 256 色，又想压进 1MB，所以做了两件关键的事：

**1. 帧差编码。** 擦除动画每帧只有一条窄带变化，因此只编码这条窄带（GIF 支持在任意 `(x, y)` 写子矩形帧）。
这样一圈动画的总编码量约等于 `(N+1)` 张整图 —— 与过渡时长、帧率都无关。所以把过渡调慢**不会增加体积**。
每张图的「停留」被合并进前一帧的 delay，成本为零。

**2. 自动降级。** 超标时按「先降分辨率、最后才降颜色」的顺序重编，并明确告知降到了多少：

```
640×360 → 480×270 → 384×216 → 320×180 → 再用 192 / 128 色
```

## 文件

| 文件 | 作用 |
|---|---|
| `index.html` | 页面结构与样式 |
| `render.js` | 帧几何、索引空间合成、帧差（纯计算，无 DOM） |
| `gif.js` | 中位切分量化器 + LZW + GIF89a 容器 |
| `app.js` | 状态、交互、预览播放器、体积逼近 |

没有第三方依赖。GIF 编码器和量化器都是自己写的 —— 因为流行的 `gifenc` 的 `writeFrame` 不支持 `x/y` 偏移，做不了帧差；而引入 WASM 版 libwebp 为了一个可选格式要塞进 700KB 不透明二进制，不符合这个项目的定位。

运行时不联网、不写本地存储、不发送任何数据。

## 开发期校验

`_dev/` 下有两个零依赖的脚本，用 `node` 直接跑：

```sh
node _dev/check-wiring.js   # 校验 index.html 的 id 与 app.js 引用一一对应、标签配对、CSS 括号平衡
node _dev/test-gif.js       # 用一个独立实现的 GIF 解码器，对编码器做逐像素往返比对
```

`test-gif.js` 还会输出体积预估。它不是单元测试框架，就是一个能立刻跑起来、不会腐烂的校验脚本。
